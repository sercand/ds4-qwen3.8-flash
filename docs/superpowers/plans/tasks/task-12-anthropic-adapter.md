## Decisions (⚠ DEVIATION where flagged)

- **D1 — render entry (T11-owned, consumed).** Both handlers need `ChatRequest → Vec<u32>`; T11 pins the single SSOT `shisu_server::tokenizer::render_prompt(&ChatRequest) -> Result<Vec<u32>, AppError>` (minijinja via T10's vendored `tokenizer/`, `tokenizers::Tokenizer::encode(&s,false)`; it has **no ctx access** — the overflow guard is handler-side, Step 8.4). T12 imports it verbatim and **never grows a second renderer** (atlas `types.rs:48-52`: "Two joiners that disagree … is the shape of bug where a serving problem gets debugged in the copy that never runs"). CPU-bound → drive via `tokio::task::spawn_blocking` (atlas `handlers.rs:168-171`).
- **D2 — blocking collector (T11-owned, consumed).** `crate::api::blocking::collect_chat_response(deltas, model, &stop) -> Result<ChatResponse, AppError>` (T11-pinned, signature confirmed): drains the `DeltaStream`, concatenates `Content`/`Reasoning`, joins `ToolCallArgs` fragments per `index` and `serde_json::from_str`s them once at `Finish` (parse failure → `Value::String(raw)` — lossless), fills one `Choice{index:0,…}`, copies `Finish{reason,usage}`, sets `model` from the 2nd arg, mints the BARE `id` via `ids::uuid_v4()` (T12's `translate.rs:10` applies the `msg_` prefix itself; T11's side prepends `chatcmpl-`). Contract T12 relies on — owned and unit-tested by T11, exercised end-to-end here through the fake engine: blocking stop matching (earliest-hit truncation, `finish_reason=Stop` + `matched_stop=Some(s)`, correcting a `Length` that actually matched — atlas `chat_blocking.rs:212-228`); `StreamDelta::Error` → `Err(AppError)`; no `Finish` ⇒ synthesized `Stop` + `Usage::default()`. T12's `From<ChatResponse>` only echoes `matched_stop` → `stop_sequence` (`translate.rs:34,43`). Streaming-side stop enforcement is T13's (engine lane, ds4-style); streaming `message_delta.stop_sequence` stays `Null` exactly as atlas `translator.rs:329` does.
- **D3 — `StreamDelta::Error` emits an SSE `error` event.** Atlas drops it (`translator.rs:340-343`), letting a failed generation end as a clean `end_turn` — the silent-truncation class `helpers.rs:68-72` warns about, and it contradicts the variant's own contract (`ir/stream.rs:43` "sent verbatim as SSE data"). Shisu's arm: after any `message_start`, emit `event: error` with data `{"type":"error","error":{"type":"api_error","message":…}}` (the `anthropic_error` body shape) then `event: message_stop`, set `finished`. `Refusal` stays dropped (atlas parity; shisu has no safety classifier).
- **D4 — auth headers.** What is enforced today (verified): T10's bearer middleware only. Additive change to T10-owned `require_auth_middleware` credential extraction: `Authorization: Bearer …` first, else `x-api-key` (the Anthropic SDK's default header; without the alias an SDK client with auth configured 401s before the handler runs). `anthropic-version` (+`anthropic-beta`): accepted, **not enforced**, logged at debug — no source validates them and version-gating is out of scope. One `or`-chain over two header names; `ct_eq` comparison unchanged.
- **D5 — `count_tokens` = 501 now, T13 implements.** ds4 has no such route (parity floor: any client working against ds4 already lives without it), so shipping it is an atlas-inherited enhancement, not a port requirement. A faithful implementation must count the **exact serving-path prompt** (atlas `handlers.rs:153-159` documents a third divergent lowering that drifted); in shisu the render/tokenize boundary is T13's scheduler (`GenerateRequest.prompt_tokens` construction), so a T12-local copy would be exactly the forbidden second renderer. T12 registers `POST /v1/messages/count_tokens → not_implemented(ApiSurface::Anthropic, "count_tokens")` (501 with the Anthropic error body via T10's `error.rs`), doc comment naming T13 as the replacement, which then mirrors atlas `handlers.rs:138-194` (same `From` lowering, image strip `:161-167`, `{"input_tokens":n}` `:190-193`).
- **Dropped machinery (no shisu equivalent):** `CurrentModel`/`model_host` (one model per process — T10 Step 6), `dump_writer`/`request_dumper` (no request dumper), `chat_completions_inner` shared pipeline (T10/T13 boundary replaces it), `openai_error_to_anthropic` (no HTTP envelope crosses layers — typed `Result`s reshape directly to `anthropic_error`).

## Stop-reason mapping (two paths, both verbatim from source)

Streaming — `convert_stop_reason(&reason.as_wire())` (`helpers.rs:58-76`; input = T9's stop-reason SSOT strings): `"stop"→"end_turn"`, `"tool_calls"→"tool_use"`, `"length"→"max_tokens"`, `"content_filter"→"refusal"`, `FINISH_REASON_TIMEOUT("timeout")→"max_tokens"` (no deadline slot in the Anthropic vocabulary; `end_turn` would lie — `:67-72`), anything else → `"end_turn"`.

Blocking — `match c.finish_reason` (`translate.rs:32-43`): `Stop if c.matched_stop.is_some() → "stop_sequence"` **and echo `stop_sequence = c.matched_stop`** (`:34,:43`; only this path ever sets a non-null `stop_sequence`), `Stop → "end_turn"`, `ToolCalls → "tool_use"`, `Length → "max_tokens"`, `ContentFilter → "refusal"`, `Other(_) → "end_turn"`.
