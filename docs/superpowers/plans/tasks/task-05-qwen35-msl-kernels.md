## Global Constraints

Master plan Rules 1–7, one line each:
1. New files only under `shisu/crates/shisu-metal/metal/qwen35/` (+ test `.rs`); `.metal` is a rule-1 allowed kind; no host C/C++.
2. 1500-LoC cap on every `.metal` file — budgets per file in the Plan table; `gated_attn` pre-split (DEVIATION 2).
3. **Arithmetic order is the contract.** The CUDA `q4e_gdn_*`/`q4e_qsa_*` kernels are the source of truth; the MSL port reproduces their reduction shapes (which lanes, which order), not a mathematically-equal re-association. Copied `kernel_mul_mm` is deletions-only.
4. No perf gate here (T6/T20 record Metal baselines); the 32 KB smem redesigns below are correctness-driven, not perf-driven.
5. No new env knobs; T4's `SHISU_METAL_SOURCE_DIR` override covers q35 files automatically.
6. Test code obeys workspace lints; errors via `shisu_core::CoreError`; no new deps.
7. No license headers.

Task-specific:
- **Measured device limits (this machine, probed via `MTLCreateSystemDefaultDevice`):** `maxThreadgroupMemoryLength = 32768` B, `maxThreadsPerThreadgroup = 1024`. The CUDA kernels' dynamic smem (recurrent 66,048 B @ :1949; chunk 99,072 B @ :1876–1879; tiled attn 49,152 B @ :3333–3335) **exceeds it** — the MSL designs below move state to registers / drop pure-cache staging, preserving every summation order.
- Reduction idiom: `__shfl_down_sync(0xffffffff,v,o)` → `simd_shuffle_down(v,o)`; `__shfl_xor_sync` → `simd_shuffle_xor`. **NEVER bare `simd_sum`** in q35 kernels (order unspecified; `glm53_kda.metal` uses it but GLM's arithmetic is not q4e's). All reductions go through `q35_warp_sum`/`q35_block_sum`/explicit xor steps in `q35_common.h`.
- Math: `__expf`→`exp`, `log1pf`→`log1p`, `rsqrtf`→`rsqrt`, `powf`→`pow`, `sincosf`→`sincos`, `__fmaf_rn`→`fmaf`; never `fast_*`. `__launch_bounds__` → dropped (block size is the dispatch contract).
- Grid/block in `LaunchArgs` are CUDA-semantics: `grid` IS the threadgroup count dispatched directly (no ceil/division), `block` = threads per threadgroup — what the copied kernels read as `tgpig`/`threads_per_threadgroup` (T2 SSOT note at ds4_metal.m:2577–2578; T4 test 7 grid (8,1,1)/block (32,2,1) → 8 threadgroups). RESOLVED with PlanT4: task-04 Step 7's earlier `ceil(grid/block)` wording was a typo, fixed in task-04 after source re-verification; all KERNELS.md grid formulas use this semantics.
